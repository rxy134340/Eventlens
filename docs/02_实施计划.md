# EventLens Implementation Plan

> For agentic workers: implement tasks in order; verify each user-observable behavior before moving on.

**Goal:** Deliver a reproducible, interactive event-research workbench and the complete written submission package.

**Architecture:** A static single-route Web app holds synthetic fixture evidence, a deterministic task orchestrator, evidence/claim validation, and local browser task state. The design keeps external data and LLM adapters explicit for later credentialed integration; demo mode never claims live data.

**Tech Stack:** HTML, CSS, vanilla JavaScript, Node.js built-in test runner, Sites static hosting.

**Spec:** `docs/01_产品设计说明.md`

## Global Constraints

- Display constructed data as constructed data at every result entry point.
- Facts require traceable source, timestamp, unit and basis when applicable.
- No deterministic price direction, return promise or direct trading instruction.
- Error and missing states must be visible, never silently converted to a normal result.
- No API keys or user privacy data in the repository.

## Review Focus

1. Missing primary source: no fact card or implied normal conclusion is produced.
2. Conflicting numerical sources: conflict remains visible and aggregate conclusion is withheld.
3. Tool failure: task reaches a partial state with a retry affordance.
4. Unsafe investment request: response redirects to evidence/risk analysis.
5. Follow-up action: user confirmation changes saved tracking state and survives reload.
